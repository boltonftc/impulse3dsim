Tank Drive

Time to make the robot move. You've printed telemetry and read the gamepad — now you'll turn those stick values into motor power. We'll start with the simplest kind of driving: tank drive.

What is tank drive?

Think about how a bulldozer or a military tank turns. It has no steering wheel — just two tracks, one on the left and one on the right. To go straight, both tracks move at the same speed. To turn, one side moves faster than the other. To spin in place, the two sides move in opposite directions.

Key idea

Tank drive steers by running the left and right sides at different speeds. Same speed = straight. Different speeds = turn. Opposite = spin.

Our robot has four mecanum wheels, but for now we'll ignore the fancy sideways stuff and drive it like a tank: the left stick controls everything — push forward to go forward, push sideways to spin.

Step 1 — Import the motor tool

Back in Your Code Package you met the import lines at the top of the file, and we promised that each new feature would bring one more. This is the first one. Driving means motors, and in the FTC library a motor is a DcMotor. Before you can use that name anywhere in your file, you have to tell Java where to find it.

What an import really is

Every class in Java has a full name that says exactly where it lives, like a full mailing address:

com.qualcomm.robotcore.hardware.DcMotor
\____________________________/ \_____/
   the folder (the "package")   the class

Read it left to right like an address: the company that wrote it (com.qualcomm), the robot library (robotcore), the hardware section (hardware), and finally the class itself (DcMotor). An import line is like saving a contact in your phone: you write the full address once at the top, and after that you can just say DcMotor everywhere else.

Without it, Java has no idea what DcMotor means. Every line that uses it turns red, and the build fails with "DcMotor cannot be resolved to a type". That's why the import comes first: add it now, and the motor code in the next step compiles as soon as you type it.

Jump to the imports at the top of MecanumDrive.java and add one more line under the ones already there:

▸ MecanumDrive.java : the imports
Type this line with the other imports⧉ Copy
import com.qualcomm.robotcore.hardware.DcMotor;
Import rules of thumb
  • Imports go at the top: after the package line, before the class. One per line, each ending in ;. Their order doesn't matter.
  • You need one import for each outside class you use by name. You'll add more in later lessons (for example, the IMU lesson adds three).
  • Pressed Reset to Start? The lesson's starting code already has this import — check that it's there and move on.
  • On a real team laptop in Android Studio, click a red class name and press Alt+Enter to add the import for you. In OnBot Java and here, you type it.

Step 2 — Set up the four motors

The robot has four motors, one at each corner: frontLeft and backLeft on the left side, frontRight and backRight on the right. For tank drive, both left motors always get the same power and both right motors get the same power — the two sides act like a tank's two tracks.

The hardware map connects a code name to a physical motor. Each motor has a configured name like "front_left_motor" that matches the robot's wiring.

Why reverse the left side?

The left motors are mounted as a mirror image of the right ones. Without reversing, sending positive power would spin the left side backward and the right side forward — the robot would spin instead of driving straight. Reversing the left side makes positive power mean "forward" for every wheel.

Go to the Drive : Setup spot in INIT and create the four motors:

▸ Go to Drive : Setup
Type this code⧉ Copy
DcMotor frontLeft  = hardwareMap.get(DcMotor.class, "front_left_motor");
DcMotor frontRight = hardwareMap.get(DcMotor.class, "front_right_motor");
DcMotor backLeft   = hardwareMap.get(DcMotor.class, "back_left_motor");
DcMotor backRight  = hardwareMap.get(DcMotor.class, "back_right_motor");
frontLeft.setDirection(DcMotor.Direction.REVERSE);
backLeft.setDirection(DcMotor.Direction.REVERSE);

Step 3 — Read the joystick

The left stick gives us two values we care about:

  • Y axis (up/down) — how much forward or backward.
  • X axis (left/right) — how much spinning.

These are doubles from -1.0 to 1.0. A gentle push might give 0.2; letting go gives 0.0. That's proportional control — the further you push, the faster the wheels go.

Remember: up is negative

Just like last lesson, pushing the stick up reports a negative Y. That feels backward, so we negate it with a minus sign so that "stick up" means "drive forward."

Step 4 — The tank math, then power

We combine drive and spin into a power for each side:

  • Left power = drive + spin
  • Right power = drive - spin

Walk through it. Straight forward: drive = 1.0, spin = 0 → left 1.0, right 1.0 → both sides equal, robot goes straight. Spin right: drive = 0, spin = 1.0 → left 1.0, right -1.0 → left forward, right backward, robot spins. We also multiply by 0.5 to stay at half speed while learning — bump it to 1.0 once you're comfortable.

Click and drag the left stick below — everything else on the controller is grayed out because this lesson only uses it. Watch the wheels and the numbers move together.

Try it — Tank Drive Simulator
Key idea

setPower() sets a motor's speed, from -1.0 (full reverse) to 1.0 (full forward); 0 stops. Both left motors get leftPower, both right motors get rightPower — that's what makes it tank drive.

Go to the Drive : Loop spot inside the run loop and add the math and the four setPower calls:

▸ Go to Drive : Loop
Type this code⧉ Copy
double drive = -gamepad1.left_stick_y;
double spin  =  gamepad1.left_stick_x;
double leftPower  = (drive + spin) * 0.5;
double rightPower = (drive - spin) * 0.5;
backLeft.setPower(leftPower);
frontLeft.setPower(leftPower);
frontRight.setPower(rightPower);
backRight.setPower(rightPower);
To Do
  • Press Build & Init, then Start.
  • Push the left stick forward — all four wheels spin to drive straight.
  • Push it sideways — the left and right wheels spin opposite ways (a tank spin).
  • Push it diagonally — one side spins faster and the robot curves.
Hint

If the robot spins when you push straight forward, you probably didn't reverse the left motors — check the two setDirection(DcMotor.Direction.REVERSE) lines. If nothing moves, make sure your setPower lines are inside the while (opModeIsActive()) braces, and that each line ends with a semicolon.

That's real driving. Right now the robot can only go forward, backward, and spin — it can't strafe sideways yet, even with mecanum wheels. A later lesson unlocks that by driving all four wheels independently instead of pairing them as left and right.
