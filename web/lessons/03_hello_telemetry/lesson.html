Hello, Telemetry

Your program runs… but it's silent. You can't see anything it's doing. In this lesson you'll fix that with telemetry — the messages a robot sends back to the Driver Hub screen. It's the single most useful tool you have for understanding what your code is really doing.

Init runs once. The loop runs forever.

You already met the two halves of an OpMode. Telemetry makes the difference easy to see:

  • The "Initialized. Press START." line is in init, so it prints one time.
  • Anything you put in the run loop prints again and again, dozens of times a second.

To prove it, you'll add a counter that ticks up by one every loop. Watching that number race upward is your first real window into the heartbeat of the robot.

Step 1 — Add a counter

Just before the run loop begins, you need a variable to count with. Find the labeled spot and add one line:

▸ Go to Telemetry : Loop Counter
Type this code⧉ Copy
int loops = 0;

This runs once, in init, so the count always starts fresh at zero. int means it holds a whole number.

Step 2 — Say something every loop

Now go inside the run loop, to the second labeled spot, and add three lines: one message, one to bump the counter, and one to show the count.

▸ Go to Telemetry : Status
Type this code⧉ Copy
telemetry.addData("Status", "Hello, Robot!");
loops += 1;
telemetry.addData("Loops", loops);
How telemetry works
  • telemetry.addData("label", value) queues up one line: a label on the left, a value on the right.
  • loops += 1; is shorthand for "add one to loops." It happens every pass through the loop.
  • The queued lines don't actually appear until telemetry.update() sends them — and that call is already written at the bottom of the loop for you. Think of addData as writing lines on a notepad, and update() as holding the notepad up to the driver.
To Do
  • Press Build & Init. You should see Initialized. Press START.
  • Press Start.
  • Watch Status hold steady at Hello, Robot! while Loops climbs fast.
Hint

If Loops shows up but never changes, the counter line is probably above the loop instead of inside it. Only code between the while (opModeIsActive()) braces repeats. If the build fails, check that each line ends with a semicolon ; and your quotes come in pairs.

That climbing number is the same loop that will soon read your gamepad and drive the wheels. You've just made the invisible visible — and you'll lean on telemetry in every lesson from here on.
