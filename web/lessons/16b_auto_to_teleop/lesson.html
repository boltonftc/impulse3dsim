Auto → TeleOp: Keep Your Place

Here's something that surprises almost every team the first time. Your autonomous drives a perfect path and parks. The buzzer goes, TeleOp starts, the driver pushes the stick straight up… and the robot drives off at an angle. What happened?

Every OpMode is a fresh start. When TeleOp begins, the robot has forgotten everything auto knew:

  • The Pinpoint resets to (0, 0) facing 0° during INIT. It has no idea where on the field it is.
  • The IMU calls “forward” whichever way the robot happened to face when TeleOp started. If auto parked the robot turned 45°, field-centric driving is now 45° off.

In this lesson you'll teach the robot to keep its place from auto into TeleOp, and to get it back when it's lost. Every robot needs this, turret or not.

Already did the Auto-Aim lesson?

Its reward used to include all of this code, so your package may already have it. Look in Localization.java for setPose and isPoseKnown. If they're there, read along but don't type them in again (Java won't allow the same method twice). Just check Step 5 and Step 6 against your code.

1. Auto leaves a note on the blackboard

Autonomous knows exactly where the robot is the whole time, because it drives paths in field coordinates. So every loop it writes the robot's position on the blackboard: a place in the FTC software that survives from one OpMode to the next. It's like leaving a note on the fridge: “I parked at (−48, 16), facing 90°.”

The note is three numbers in an array: x, y, and the heading in degrees. It's stored under a name, "autoPose", so TeleOp can find it.

  • Auto writes the note every loop, not just at the end, because the 30-second timer can stop auto partway through a path.
  • Autos saved by the simulator's Path Capture tool already write the note. Hand-written autos like SimpleAuto need one line.

2. Give Localization a place to put it

TeleOp needs a way to tell the Pinpoint “you're actually here.” That's setPose(): it hands the Pinpoint a field position and heading. The Pinpoint keeps counting from there, so from then on every reading is in real field inches.

We also add a flag, poseKnown. It starts false and turns true the moment somebody tells us where we are. And we add HOME, a spot you can find by feel; section 5 explains it.

Step 2 — Add HOME, setPose(), and isPoseKnown()

Add these below getDistanceFromStartInches(), still inside the class:

▸ Localization.java : Localization : Getters
Type this into Localization.java⩢ Copy
    // HOME: a spot the drivers can find by feel. Back of the robot against YOUR drivers' wall,
    // facing away from it, left side on the loading zone's right-hand tape line.
    // These numbers come from the simulator -- MEASURE your field and your robot!
    private static final double ROBOT_WIDTH  = 18.0;   // inches, side to side
    private static final double ROBOT_LENGTH = 18.0;   // inches, front to back
    private static final double TAPE_X = -22.0;        // the loading zone's right-hand tape line
    private static final double WALL_Y = -71.0;        // the inside face of the drivers' wall
    private static final double HOME_X = TAPE_X + ROBOT_WIDTH / 2;    // -13: the robot's CENTER, not its side
    private static final double HOME_Y = WALL_Y + ROBOT_LENGTH / 2;   // -62
    private static final double HOME_HEADING = 90.0;                  // facing away from the drivers

    private boolean poseKnown = false;   // stays false until auto hands us a pose, or the driver resets at HOME

    /** Tell the Pinpoint where the robot is right now: field inches, heading in degrees. */
    public void setPose(double xInches, double yInches, double headingDegrees) {
        latestPose = new Pose2D(DistanceUnit.INCH, xInches, yInches, AngleUnit.DEGREES, headingDegrees);
        if (pinpoint != null) {
            pinpoint.setPosition(latestPose);
        }
        poseKnown = true;
    }

    /** The robot is parked at HOME: that's exactly where we are. */
    public void setPoseToHome() {
        setPose(HOME_X, HOME_Y, HOME_HEADING);
    }

    /** True once we know where we are on the field (from auto, or a HOME reset). */
    public boolean isPoseKnown() {
        return poseKnown;
    }

3. TeleOp reads the note

Right after START, TeleOp looks for the note. If it's there, it hands the position to setPose(), and the robot knows exactly where it is from the very first second of TeleOp.

  • TeleOp uses remove, which reads the note and throws it away. If you stop and restart TeleOp later in practice, it won't trust an old note from a robot that may have been carried somewhere else.
  • The note is an Object, so we check it really is a double[] before using it (instanceof). No note at all? Then fromAuto is null, the check fails, and we simply skip it.
  • We wait until after START to call setPose. The Pinpoint spends a moment calibrating after INIT, and a pose sent during that moment can get erased.

We'll also need a stopwatch for the HOME reset in section 5, so we set that up here too.

4. No note? Don't guess

If there's no note (you ran TeleOp by itself, or the robot was restarted between auto and TeleOp), the robot does not know where it is. A guess would be worse than nothing: anything that depends on the position would confidently do the wrong thing. So the robot keeps poseKnown false and simply waits to be told: by auto's note, or by a HOME reset.

Let's put that flag on the Driver Hub, so the drivers can see it at a glance.

5. HOME: a reset button you can find by feel

HOME is one spot right in front of your drivers, next to the loading zone, that the robot can be put in exactly, without measuring:

  • Back against your drivers' wall — that pins down how far from the drivers it is (y).
  • Facing straight away from the wall — that pins down the heading: 90°.
  • Left side on the loading zone's right-hand tape line — that pins down x.

The position is the robot's center, so we add half the robot's size: with an 18″ × 18″ robot, HOME is at x = −22 + 9 = −13 and y = −71 + 9 = −62, facing 90°. That's what the constants in Step 2 work out.

Hold RB for half a second, and only at HOME

One button fixes both of the robot's “where am I?” answers at once:

  • It resets the IMU, so “forward” is away from the drivers.
  • It tells the Pinpoint it's at HOME, so the robot knows exactly where it is.

The rule: only press RB at HOME. Press it anywhere else and the robot will believe it's at HOME when it isn't.

Why hold for half a second instead of a quick tap? So a bumped button in the middle of a match can't scramble the robot's idea of where it is. The ElapsedTime stopwatch restarts every loop that RB is up; only when it reaches 0.5 seconds does the reset happen, and homeDone makes sure it happens just once per hold.

HOME is also the fix for drift. Odometry is very good, but after two minutes of bumping into robots it can be off by an inch or two. A quick hold of RB at HOME wipes the slate clean.

6. Field-centric that stays right after auto

Now the fix for the robot that drove off at an angle. Field-centric driving needs to know which way the robot faces compared to the drivers. Until now it asked the IMU, and the IMU only knows which way the robot faced when TeleOp started.

The Pinpoint doesn't have that problem. Auto told it the real start pose, and the note carried that pose into TeleOp, so its heading is a true field heading. So once the pose is known, field-centric uses the Pinpoint's heading instead.

There's one small conversion. On the field, facing away from your drivers is heading 90°. But field-centric calls that direction 0 (“straight ahead”). So we subtract 90:

heading = Math.toRadians(robot.localization.getHeadingDegrees() - 90);

If the pose isn't known yet, we fall back to the IMU, just like before. And HOME lines both up: at HOME the Pinpoint says 90° (so this gives 0) and the IMU is reset to 0.

Step 6 — Replace the heading code

Open the IMU : Heading section. Delete what's there now (the old double heading = imu... line, the two Heading telemetry lines, and the old if (gamepad1.right_bumper) { imu.resetYaw(); }) and type this in its place. The quick RB tap is replaced by the HOME reset.

▸ MecanumDrive.java : IMU : Heading
Type this into MecanumDrive.java, replacing the old heading code⩢ Copy
            // Field-centric "forward": once we know our field pose (from auto or HOME), use the Pinpoint's
            // FIELD heading -- the IMU only knows which way we faced when TeleOp started.
            // 90 deg on the field = facing away from your drivers = field-centric 0, so subtract 90.
            double heading;
            if (robot.localization.isPoseKnown()) {
                heading = Math.toRadians(robot.localization.getHeadingDegrees() - 90);
            } else {
                heading = imu.getRobotYawPitchRollAngles().getYaw(AngleUnit.RADIANS);   // no pose yet: same as before
            }
            telemetry.addData("Heading (deg)", Math.toDegrees(heading));
            telemetry.addData("Heading (rad)", heading);

            // HOME reset: park at HOME and hold RB for half a second. Resets field-centric "forward"
            // (the IMU) AND tells odometry exactly where the robot is. Only press it at HOME!
            if (!gamepad1.right_bumper) {
                rbHeld.reset();          // the stopwatch restarts whenever RB is up
                homeDone = false;
            } else if (rbHeld.seconds() >= 0.5 && !homeDone) {
                imu.resetYaw();
                robot.localization.setPoseToHome();
                homeDone = true;
            }
            if (homeDone) telemetry.addLine("HOME: position reset. Let go of RB.");
Why double heading; on its own line?

We declare the variable first, without a value, then the if/else gives it one either way. Java checks that every path sets it before it's used, so you can't forget a case.

7. The Driver Hub's TeleOp preselect

In a real match there are only 8 seconds between auto and TeleOp. Scrolling for the right TeleOp under that pressure is how teams end up running the wrong program. The Driver Hub has a helper for that.

  • When you select an Autonomous, a faint button appears in the lower-left of the Driver Hub. Tap it and pick your TeleOp: it turns solid and shows the name.
  • When auto ends (on its own, or when the 30-second timer stops it), the Driver Hub switches to that TeleOp for you. It does not run it: for safety, the drivers still press INIT and then START.
  • If someone presses STOP during auto, the switch is cancelled.
Optional: set it in code

Add preselectTeleOp to your auto's annotation, and the Driver Hub turns the preselect on by itself every time you pick that auto. The name must match your TeleOp's name exactly.

@Autonomous(name = "SimpleAuto", group = "BIOBUZZ", preselectTeleOp = "MecanumDrive")
