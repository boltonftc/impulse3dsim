IMU Heading

Your robot has a tiny sensor called an IMU — an Inertial Measurement Unit. Inside is a gyroscope that tracks how far the robot has rotated. Its most useful output is heading: the direction the robot is currently facing, like a compass.

Key idea

An IMU measures rotation. When the robot starts, its heading is 0. Spin counter-clockwise (to the left) and heading grows toward +π; spin clockwise and it drops toward -π. FTC code reads it in radians because Math.cos and Math.sin expect radians.

Why do we care? Without a heading, "forward" on the stick means "whatever way the robot is pointed." The moment the robot spins around, forward looks backward to the driver. In the next lesson we will use this heading to make forward always mean away from the driver — field-centric driving. First we need the heading itself.

1 — Initialize the IMU

Just like a motor, you fetch the IMU from the hardware map by name ("imu") during INIT, then initialize it. Open MecanumDrive.java and jump to the setup spot:

IMU imu = hardwareMap.get(IMU.class, "imu");   // grab the IMU from the config, by the name "imu"

// Wake the sensor up and tell it how the Control Hub is bolted onto the robot,
// so it knows which way is up and which way the robot faces.
imu.initialize(new IMU.Parameters(                            // hand the IMU a settings bundle...
    new RevHubOrientationOnRobot(                             //   ...that describes the hub's mounting:
        RevHubOrientationOnRobot.LogoFacingDirection.UP,      //      the REV logo points UP
        RevHubOrientationOnRobot.UsbFacingDirection.FORWARD)));//     the USB ports point FORWARD

This block does two things. The first line fetches the IMU from the hardware map by its config name "imu" — exactly like fetching a motor. The second statement, imu.initialize(…), wakes the sensor up and tells it how it is mounted.

Read nested code from the inside out

That initialize line looks intimidating because it is three new objects nested one inside another. The trick is to read it from the innermost parentheses outward, like simplifying a math expression:

  1. new RevHubOrientationOnRobot(LogoFacingDirection.UP, UsbFacingDirection.FORWARD) — the innermost piece. It describes how the Control Hub is mounted on the robot: the REV logo faces UP, the USB ports face FORWARD.
  2. new IMU.Parameters( … ) — wraps that orientation into a tidy settings bundle the IMU knows how to read.
  3. imu.initialize( … ) — hands the whole bundle to the IMU so it can start up knowing which way is up and which way is forward.

You will see this “new inside new” shape often in FTC code. The move is always the same: find the innermost part, understand it, then read outward.

Why does the mounting matter? The IMU figures out rotation relative to gravity and its own body. If you told it the hub was lying flat when it is really standing on its side, every heading it reported would be wrong. UP and FORWARD match our robot and the most common real mounting — on a physical robot you would change these to match how your hub is actually bolted on.

The imports for IMU, RevHubOrientationOnRobot, and AngleUnit are already added for you at the top of the file.

2 — Read the heading every loop

Now read the heading inside the run loop, show it on the Driver Hub in both radians and degrees, and let the driver re-zero it with the right bumper. Jump to the loop spot:

Type this code⩢ Copy
double heading = imu.getRobotYawPitchRollAngles().getYaw(AngleUnit.RADIANS);  // how far the robot has turned, in radians

telemetry.addData("Heading (deg)", Math.toDegrees(heading));  // show it in degrees (easy for humans to read)
telemetry.addData("Heading (rad)", heading);                  // ...and in radians (what the math will use)

if (gamepad1.right_bumper) {  // driver presses the right bumper...
    imu.resetYaw();           // ...to call "wherever I'm pointing now" the new zero heading
}

That chain reads simply: getRobotYawPitchRollAngles() hands back all three orientation angles, and .getYaw(AngleUnit.RADIANS) pulls out just the one we want — heading — in radians.

What reset does

imu.resetYaw() does not move the robot. It tells the IMU "whichever way I am pointing right now is the new 0." Drivers use it at the start of a match so the robot's current facing becomes forward, no matter how it was placed on the field.

Hint

The heading number only changes when the robot rotates. Driving straight or strafing leaves it alone — that is exactly what you want. Notice it stays between -π and +π (about ±3.14), never counting past a half turn.

The heading is now flowing into the drivebase every loop — but the drive code still ignores it, so the robot drives the same as before. Next lesson we put this heading to work.
