IMU Heading

Your robot has a tiny sensor called an IMU — an Inertial Measurement Unit. Inside is a gyroscope that tracks how far the robot has rotated. Its most useful output is heading: the direction the robot is currently facing, like a compass.

Key idea

An IMU measures rotation. When the robot starts, its heading is 0. Spin counter-clockwise (to the left) and heading grows toward +π; spin clockwise and it drops toward -π. FTC code reads it in radians because Math.cos and Math.sin expect radians.

Why do we care? Without a heading, "forward" on the stick means "whatever way the robot is pointed." The moment the robot spins around, forward looks backward to the driver. In the next lesson we will use this heading to make forward always mean away from the driver — field-centric driving. First we need the heading itself.

1 — Initialize the IMU

Just like a motor, you fetch the IMU from the hardware map by name ("imu") during INIT, then initialize it. Open MecanumDrive.java and jump to the setup spot:

IMU imu = hardwareMap.get(IMU.class, "imu");
imu.initialize(new IMU.Parameters(
    new RevHubOrientationOnRobot(
        RevHubOrientationOnRobot.LogoFacingDirection.UP,
        RevHubOrientationOnRobot.UsbFacingDirection.FORWARD)));

RevHubOrientationOnRobot tells the IMU how the Control Hub is mounted — logo facing UP, USB ports facing FORWARD. That matches our robot (and the most common real mounting). The imports for IMU, RevHubOrientationOnRobot, and AngleUnit are already added for you at the top of the file.

2 — Read the heading every loop

Now read the heading inside the run loop, show it on the Driver Hub in both radians and degrees, and let the driver re-zero it with the right bumper. Jump to the loop spot:

Type this code⩢ Copy
double heading = imu.getRobotYawPitchRollAngles().getYaw(AngleUnit.RADIANS);
telemetry.addData("Heading (deg)", Math.toDegrees(heading));
telemetry.addData("Heading (rad)", heading);
if (gamepad1.right_bumper) {
    imu.resetYaw();
}

That chain reads simply: getRobotYawPitchRollAngles() hands back all three orientation angles, and .getYaw(AngleUnit.RADIANS) pulls out just the one we want — heading — in radians.

What reset does

imu.resetYaw() does not move the robot. It tells the IMU "whichever way I am pointing right now is the new 0." Drivers use it at the start of a match so the robot's current facing becomes forward, no matter how it was placed on the field.

Hint

The heading number only changes when the robot rotates. Driving straight or strafing leaves it alone — that is exactly what you want. Notice it stays between -π and +π (about ±3.14), never counting past a half turn.

The heading is now flowing into the drivebase every loop — but the drive code still ignores it, so the robot drives the same as before. Next lesson we put this heading to work.
